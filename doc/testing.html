testing

testing.txt 适用于 Vim 9.2 版本。 最近更新: 2026年7月 VIM 参考手册 by Bram Moolenaar 译者: Willis 测试 Vim 和 Vim 脚本 testing-support 表达式求值见 eval.txt 。本文档详述如何使用 Vim 脚本编写测试。既可用于 Vim 自 身测试，也可用于插件测试。 1. 测试 Vim testing 2. 测试函数 test-functions-details 3. 断言函数 assert-functions-details

1. 测试 Vim testing

Vim 在编译完成后，可执行测试，通常使用 "make test"。测试文件位于目录 "src/testdir"。 在不同时间点，引入了两类测试: test20.in 老风格测试，仅用于微小编译版本 test_something.vim 新风格测试 new-style-testing 新增测试必须使用新风格。测试脚本命名方式为 test_<feature>.vim (<feature> 替换 为待测功能名)。这类测试脚本使用 assert_equal() 等函数，将测试命令和预期结果 放在一处。 old-style-testing 老风格测试仅用于测试不带 +eval 特性的 Vim。 更多信息详见 src/testdir/README.txt 文档。

3. 断言函数 assert-functions-details

assert_beeps({cmd}) assert_beeps() 执行 {cmd}，命令 不 产生响铃或可视响铃时，向 v:errors 添加错 误信息。 另见 assert_fails() 、 assert_nobeep() 和 assert-return 。 也可用作 method : GetCmd()->assert_beeps() 返回类型: Number assert_equal() assert_equal({expected}, {actual} [, {msg}]) {expected} 不等于 {actual} 时，向 v:errors 添加错误信息并返 回 1。否则返回零。 assert-return 错误信息格式为 "Expected {expected} but got {actual}"。{msg} 给出时，加到错误信息开头。从脚本调用时，开头还会附带断言所在位 method ，基是作为第二个参数传递的: mylist->assert_equal([1, 2, 3]) 返回类型: Number assert_equalfile() assert_equalfile({fname-one}, {fname-two} [, {msg}]) 文件 {fname-one} 和 {fname-two} 文本不完全一致时，向 v:errors 添加错误信息。另见 assert-return 。 如果文件 {fname-one} 或 {fname-two} 不存在，错误信息会指明该情 况。 主要配合 terminal-diff 使用。 也可用作 method : GetLog()->assert_equalfile('expected.log') 返回类型: Number assert_exception({error} [, {msg}]) assert_exception() v:exception 不包含字符串 {error} 时，向 v:errors 添加错误 信息。另见 assert-return 。 用于断言命令抛出异常。建议使用错误号加冒号，可规避语言翻译带来 的匹配问题: try commandthatfails call assert_false(1, '命令本应失败') catch call assert_exception('E492:') endtry 返回类型: Number assert_fails() assert_fails({cmd} [, {error} [, {msg} [, {lnum} [, {context}]]]]) 执行 {cmd}，命令 不 产生错误或错误信息中找不到 {error} 时，向 v:errors 添加错误信息。另见 assert-return 第二个模式 (如有) 需要匹配最后一条错误信息。 仅产生一条错误信息时，两个模式必须都匹配。可用于检查是否仅出现 一条错误。 要只匹配最后一条错误信息，首错模式可用空串: call assert_fails('cmd', ['', 'E987:']) {msg} 为空时不使用。此参数传入空串可用于传入后面的 {lnum} 参数 并获取缺省信息。 E1115 {lnum} 给出且非负时，如果
