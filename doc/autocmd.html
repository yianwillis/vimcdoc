1. 简介 autocmd-intro

在文件读写，缓冲区或窗口进出，甚至 Vim 退出等时刻，都可指定要自动执行的命令。 例如，可创建一个自动命令，对匹配 *.c 的文件自动置位 'cindent' 选项。还可用自动 命令来实现诸如编辑压缩文件 (见 gzip-example ) 等的高级特性。一般来说，自动命 令在 .vimrc 或 .exrc 文件里设置。 E203 E204 E143 E855 E937 E952 警告: 自动命令功能强大，甚至会导致意想不到的副作用。小心文本不要遭到破坏。 - 最好能先在一个能够牺牲的副本上进行测试。 例如: 如果使用自动命令在文件开始编辑时进行解压，应确保写回时的自动命令能正确 执行压缩。 - 准备好中途出现的错误 (例如，磁盘没有空间)。Vim 通常能够撤销缓冲区里的改动， 但文件的其他方面改动需要手动清理 (例如，压缩被解压的文件)。 - 如果 BufRead* 等事件允许编辑一个压缩文件，FileRead* 等事件应该完成同样的操作 (这使得在一些特殊情况下内容可以恢复)。如果可能，尽量用相同的自动命令处理 File* 和 Buf* 事件。 建议用法: - 总是使用自动命令组，需要时方便删除自动命令。 - 保持命令本身简短，繁重工作可用函数完成。 - 确保定义所在的脚本被重复执行时，自动命令不会被重复定义。 Vim9 脚本示例: autocmd_add([{replace: true, group: 'DemoGroup', event: 'BufEnter', pattern: '*.txt', cmd: 'call DemoBufEnter()' }]) 老式脚本示例: >vim call autocmd_add([#{replace: v:true, \ group: 'DemoGroup', \ event: 'BufEnter', \ pattern: '*.txt', \ cmd: 'call DemoBufEnter()' \ }])

2. 定义自动命令 autocmd-define

:au :autocmd :au[tocmd] [group] {event} {aupat} [++once] [++nested] {cmd} 将 {cmd} 加入命令列表，以便 Vim 对匹配 {aupat} 模式的 文件在发生 {event} 事件时，自动执行 {cmd}。 见 autocmd-patterns 。 此处 {event} 不能是 "*"。 E1155 注意: 引号视为本命令参数的一部分，不用作注释引导。 Vim 总把 {cmd} 加到已有的自动命令之后，从而保证自动命 令的执行顺序与其定义的顺序相同。 关于 [++nested]，参见 autocmd-nested 。为了后向兼容， 也可用 "nested" (无 ++)，但 Vim9 脚本里不接受。 E1078 autocmd-once [++once] 给出时，命令仅执行一次，然后删除 ("一次性")。 特殊模式 <buffer> 或 <buffer=N> 用于定义缓冲区局部自动命令。见 autocmd-buflocal 。 :autocmd 出现在 Vim9 脚本中 ( :vim9script 开头或 :def 函数里定义的脚本) 时，{cmd} 会在 Vim9 脚本环境下运行。此处取决于 autocmd 定义所在的位置，而非事 件触发位置。 :autocmd-block 类似用户命令 :command 定义，{cmd} 可为命令块，参见 :command-repl 。示例: au BufReadPost *.xml { setlocal matchpairs+=<:> /<start } 在 Vim 脚本里可用 autocmd_add() 函数，新增一组自动命令和自动命令组。需要在 :autocmd 里使用 :execute 时，这个方法更好。 注意: 要在 ":autocmd" 命令之后紧跟其他命令，'|' 必须在期待模式出现的位置出现。 以下可行: :augroup mine | au! BufRead | augroup END 但下列命令会将 "augroup" 视为所定义命令的一部分: :augroup mine | au! BufRead * | augroup END :augroup mine | au BufRead * set tw=70 | augroup END 正确方法是将组名放入命令本身: :au! mine BufRead * :au mine BufRead * set tw=70 或者用 :execute : :augroup mine | exe "au! BufRead *" | augroup END :augroup mine | exe "au BufRead * set tw=70" | augroup END autocmd-expand 注意 ":autocmd" 参数内的特殊字符 (如 "%"、"<cword>") 不会在定义时被展开，而是 在事件发生期间，{cmd} 执行时才进行。唯一的例外是 "<sfile>" 会在定义时被展开。 例如: :au BufNewFile,BufRead *.html so <sfile>:h/html.vim 这里 Vim 会把 <sfile> 展开为该行所在文件名。不过，<sfile> 在函数里的用法不同， 为此，最好用 :execute 并带 <script>，达成相同效果: :exe $'au BufNewFile,BufRead *.html so {expand("<script>:h")}/html.vim' 即使已有定义，:autocmd 命令仍会将同一命令加入自动命令列表。如果 .vimrc 被执行 两次，自动命令就会出现两次。要避免此问题，可将自动命令定义放入自动命令组，方便 对先前定义的命令先进行清理: augroup vimrc " 清除 vimrc 组全部的自动命令 autocmd! au BufNewFile,BufRead *.html so <sfile>:h/html.vim augroup END 如果不想删除所有的自动命令，可用变量确保 Vim 仅定义自动命令一次: :if !exists("autocommands_loaded") : let autocommands_loaded = 1 : au ... :endif {group} 参数省略时，Vim 默认使用当前组 (由 ":augroup" 定义)；否则，Vim 使用 {group} 定义的组。注意 该 [group] 必须事先定义。定义新组不能用 ":au group ..." 而应该用 ":augroup"。 测试自动命令时，'verbose' 选项可能很有用: :set verbose=9 这个设置使得 Vim 在执行自动命令时回显之。 脚本里定义自动命令时，可调用脚本局部函数或脚本局部映射。在事件触发并执行相应命 令时，该命令会在定义脚本的上下文内执行。如果命令里用到 <SID> ，这一点很重要。 执行命令时，后面的命令消息会覆盖前一个的，这种情况与手动执行命令时不同。屏幕通 常不会滚动，所以也不会有按-回车的提示。但当一个命令输出两条消息时，这种情况仍 会发生。

8. 组 autocmd-groups

自动命令可以进行分组，以便统一删除或执行。例如，所有语法高亮相关的自动命令可放 入 "highlight" 组，这样在 GUI 启动时，可用 `:doautoall highlight BufRead` 一并 执行。 未指定特殊组名时，Vim 默认使用缺省组。缺省组无名。不能单独执行缺省组中的全部自 动命令；仅当为所有组执行自动命令时，才会执行缺省组自动命令。 自动执行自动命令时，Vim 通常使用所有组的自动命令。仅当通过 :doautocmd 或 :doautoall 手动执行自动命令、以及定义或删除自动命令时，组才有作用。 组名可以包含任何非空白字符。但保留组名 "end" (包括其大写形式)。 组名区分大小写。注意 这与事件名不同！ :aug :augroup :aug[roup] {name} 定义后续 ":autocmd" 命令所属的自动命令组名。 名字 "end" 或者 "END" 会选择缺省组。 为了避免混淆，应避免使用和已有 {event} 名重复 的名字，否则很可能与用户预期不符。 :augroup-delete E367 W19 E936 :aug[roup]! {name} 删除自动命令组 {name}。如果该组中还有自动命令 存在，请勿删除！否则会收到系统警告。如果该组是 当前组，甚至会报错 E936。 要在特定组中定义自动命令，可按以下步骤操作: 1. 用 ":augroup {name}" 选择组。 2. 用 ":au!" 清除该组中原有的自动命令。 3. 定义所需自动命令。 4. 用 "augroup END" 切换回缺省组。 示例: >vim :augroup uncompress : au! : au BufEnter *.gz %!gunzip :augroup END 这套方案可以防止自动命令被重复定义 (例如，再次执行 .vimrc 文件后)。 FileExplorer Vim 识别以下特殊命令组: FileExplorer。该组存在时，Vim 假定目录可以编辑，编辑时 会触发插件以列出目录中的文件。 netrw 插件使用此特性，从而可用: browse edit
