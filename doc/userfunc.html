3. 函数内清理操作 :defe :defer :defe[r] {func}({args}) 当前函数结束时调用 {func}。{args} 在本命令定义时求值。 函数内的一条命令常会产生全局影响，函数退出时必须撤销。要在各种场景下都能正确清 理，是非常麻烦的操作。尤其是出现意外错误时，虽然用 try/finally 代码块处理，但 需要多个清理动作时会变得复杂。 本命令是一种更简便的方案。它会在当前函数返回时调度对另一函数的一次调用，无论执 行过程是否出错，都会执行该调用。示例: >vim func Filter(text) abort call writefile(a:text, 'Tempfile') call system('filter < Tempfile > Outfile') call Handle('Outfile') call delete('Tempfile') call delete('Outfile') endfunc 如果执行过程中发生中断，临时文件 'Tempfile' 和 'Outfile' 不会被删除。本命令可 避免这个问题: >vim func Filter(text) abort call writefile(a:text, 'Tempfile') defer delete('Tempfile') defer delete('Outfile') call system('filter < Tempfile > Outfile') call Handle('Outfile') endfunc 注意 "Outfile" 的清理调度放在 system() 之前，因为即使 system() 失败，该文 件也有可能被创建。 延迟函数按逆序调用，后添加的先执行。一个无用的例子: >vim func Useless() abort for s in range(3) defer execute('echomsg "number ' .. s .. '"') endfor endfunc 现在 :messages 会显示: number 2 number 1 number 0 延迟函数的返回值会被丢弃。函数后不支持链式调用，如 "->func" 和 ".member"。当前 不支持 `:defer GetArg()->TheFunc()` 通过方法形式调用函数，后续版本可能会。 延迟函数内部出错会报告，但不会中止其他延迟函数的执行，也不会影响延迟函数之外的 执行。 本命令不接受范围。函数可为携带额外参数的偏函数，但不支持字典函数。 E1300 :def 函数内， :defer 可以搭配匿名函数使用。示例: def Fn() set lazyredraw defer () => { set lazyredraw& }() enddef

4. 自动加载函数 autoload-functions 当使用数量众多或体积庞大的函数时，可仅在函数被调用时才自动提供其定义。有两种实 现方法: 通过自动命令，或通过 'runtimepath' 里的 "autoload" 目录。 Vim9 脚本还有针对导入脚本的自动加载机制，见 import-autoload 。 通过自动命令 相关介绍请参考用户手册 41.14 一节。 自动命令适用于长 Vim 脚本文件插件。可定义自动命令，然后用 :finish 快速结束脚 本。这会加快 Vim 启动速度。之后由自动命令再次加载同一脚本文件，通过设置变量跳 过 :finish 命令。 具体来说，使用 FuncUndefined 自动命令事件，模式匹配等待定义函数。例如: :au FuncUndefined BufNet* source ~/vim/bufnetfuncs.vim "~/vim/bufnetfuncs.vim" 中需要定义 "BufNet" 开头的函数。另见 FuncUndefined 。 通过 autoload 脚本 autoload E746 相关介绍请参考用户手册 52.2 一节。 在 "autoload" 目录里定义脚本是一种更简单的方式，但文件名必须严格符合规范。可自 动加载的函数名形如: :call filename#funcname() 这类函数总是全局函数，因此在 Vim9 脚本中，需要加上 "g:": :call g:filename#funcname() 调用这类函数时，如果尚未定义，Vim 会在 'runtimepath' 下的 "autoload" 目录里搜 索对应脚本文件 "filename.vim"。例如 "~/.vim/autoload/filename.vim"。该脚本文件 内应定义函数如下: function filename#funcname() echo "Done!" endfunction 如果文件不存在，Vim 还会在 'packpath' 的 "start" 子目录中搜索，即使这些包尚未 加入 'runtimepath'，也可以在 .vimrc 中调用其中的函数 (见 packages )。 文件名必须与函数中 # 之前的部分必须完全一致，而定义的函数名必须和调用时所用名 称完全相同。在 Vim9 脚本中，需要加上 "g:" 前缀: function g:filename#funcname() 编译型函数的定义格式: def g:filename#funcname() 支持子目录。函数名里每一个 # 相当于路径分隔符。例如，调用: :call foo#bar#func() 时，Vim 会在 'runtimepath' 里查找文件 "autoload/foo/bar.vim"。 读取尚未赋值的此类变量同样触发自动加载: :let l = foo#bar#lvar 但如果该 autoload 脚本已加载，访问不存在的变量不会再次加载脚本。 给此类变量赋值不会触发特殊逻辑。可用于在加载 autoload 脚本前传递设置: :let foo#bar#toggle = 1 :call foo#bar#func() 注意 如果调用应由 autoload 脚本提供、但实际未定义的函数，会报函数缺失错误。即 使修正 autoload 脚本后，也不会自动重新加载，而需要重启 Vim 或手动加载该脚本。 另外注意 两个脚本文件互相调用对方尚未定义的函数无效。避免在顶层作用域使用自动 载入功能。 Vim9 脚本中，如果函数定义时采用的名称包含 "#" 字符，会报错 E1263 。应当使 用不带 "#" 的名称，并配合 :export 导出函数。 提示: 分发一组脚本时，可用 vimball 工具打包。另见用户手册 distribute-script 一节。 vim:tw=78:ts=8:noet:ft=help:norl:
