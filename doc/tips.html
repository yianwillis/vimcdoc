查找标识符的引用位置 ident-search

用户应该已经熟知 tags 可用于跳转到函数或变量的定义位置。但有时可能希望跳转到 函数和变量所有的使用位置。有两种实现方式: 1. 使用 :grep 命令。在大多数 Unix 系统上可用，但速度较慢 (需要读取全部文件)， 且仅可在单个目录内搜索。 2. 使用 ID 工具集。速度快，支持多目录。依靠数据库存储定位信息。需要额外安装程 序，并且要维护数据库保持更新。 使用 GNU id 工具集 (id-tools): 所需环境: - 安装 GNU id 工具集 (mkid 用于生成 ID 数据库，lid 用于调用相关宏)。 - 当前目录下存在名为 "ID" 的标识符数据库文件。可通过 "mkid file1 file2 .." 外 壳命令创建。 在 .vimrc 文件里加入: map _u :call ID_search()<Bar>execute "/\\<" .. g:word .. "\\>"<CR> map _n :n<Bar>execute "/\\<" .. g:word .. "\\>"<CR> function! ID_search() let g:word = expand("<cword>") let x = system("lid --key=none " .. g:word) let x = substitute(x, "\n", " ", "g") execute "next " .. x endfun 使用方法是，将光标放在单词上，按下 "_u"，vim 会加载包含这单词的文件。在相同文 件中按 "n" 查找单词下一处匹配。按 "_n" 切换到下一个文件。 该方案已在 id-utils-3.2 版本 (最近的 gnu ftp 镜像服务器上的归档包名) 测试通 过。 [本思路来自 Andreas Kutschera]

在 xterm 中切换屏幕 xterm-screens xterm-save-screen

(来源: comp.editors，Juergen Weigert 对一个问题的回复) :> 另一个问题就是退出 vim 后，屏幕保持原样，也就是说: 我正在查看 (编辑) 的内容 :> 留在屏幕上。之前执行的命令 (如 "ls") 的输出丢失了，在滚动缓冲区里也找不到。 :> 我知道有办法在退出 vim 或其他类 vi 编辑器后恢复屏幕，只是不知道怎么做。请帮 :> 助我，谢谢。 : : 我想其他人可以回答这个问题。但我猜想在特定的 xterm 配置下， vim 和 vi 的行为 : 应该一致。 二者行为未必一致，这可能是 termcap 和 terminfo 的差异导致。要知道描述终端属性 有两套数据库: termcap 和 terminfo。当两套数据库的条目有出入，且一个程序使用 terminfo，而另一个使用 termcap 时，就会产生行为差异 (请参见: +terminfo )。 针对此问题，重点是以下控制序列: ^[[?47h 和 ^[[?47l。它们用来在 xterm 备用和主 屏幕缓冲区之间切换。一个简易临时解决方案是使用以下命令序列 echo -n "^[[?47h"; vim ... ; echo -n "^[[?47l" (符号 ^[ 代表 ESC 字符，后文会看到数据库里写作 \E)。 Vim 启动时，会向终端输出 termcap 的 ti 项目 (terminfo 中名为 smcup)。退出时输 出 te 项目 (terminfo 中名为 rmcup)。因此，这两项应是上述控制序列正确的存放位 置。 可将系统实际 xterm termcap 项目 (位于 /etc/termcap) 和 xterm terminfo 项目 (用 "infocmp -C xterm" 获取) 进行对比。两者都应包含类似以下的形式: :te=\E[2J\E[?47l\E8:ti=\E7\E[?47h: 附: 如果发现二者存在差异，可建议系统管理员彻底检查整套 termcap 和 terminfo 数 据库的一致性。 备注 1: 在 feature.h 中定义 FEAT_XTERM_SAVE 后重新编译 Vim，则内置 xterm 数据 库就会包含上述的 "te" 和 "ti" 条目。 备注 2: 要禁止屏幕切换，又不想修改 termcap，可在 .vimrc 中加入: :set t_ti= t_te=

插入模式下滚动 scroll-insert

处于插入模式时，要查看屏幕外的内容，可用 CTRL-X CTRL-E 和 CTRL-X CTRL-Y 滚屏。 i_CTRL-X_CTRL-E 可用以下映射方便操作: :inoremap <C-E> <C-X><C-E> :inoremap <C-Y> <C-X><C-Y> (按本义输入，确保 'cpoptions' 选项不含 '<' 标志位 cpo-< )。 不过映射后，将无法使用 i_CTRL-E 复制光标上一行/下一行的文本。 也可将 'scrolloff' 调大，确保看到光标附近更多的上下文。如果 'scrolloff' 取值大 于窗口高度的一半，在上下移动光标时，光标会始终保持在窗口中间，而文本自动滚动。

统计单词个数、行数等 count-items

要统计当前缓冲区中任意模式的匹配出现频率，可用 :substitute 命令并加 'n' 标志 位以避免实际替代。Vim 报告的替代次数就是模式匹配次数。例如: :%s/./&/gn 字符数 :%s/\i\+/&/gn 单词数 :%s/^//n 行数 :%s/the/&/gn 任意位置的 "the" 出现次数 :%s/\<the\>/&/gn 作为单词的 "the" 出现次数 可复位 'hlsearch' 或执行 :nohlsearch 关闭高亮。 无匹配时如果不想报错，加上标志位 'e'。 适用于可视模式的另一种统计数据的方法是 v_g_CTRL-G 。 多文件查找匹配可用 :vimgrep 。 count-bytes 要统计字节数，可用以下方法: 可视选中所需字符 (也可用列块选择) 用 y 复制文本 调用 strlen() 函数: :echo strlen(@") 这里换行符会被计为一个字节。

恢复光标位置 restore-position

有时需要编写映射时，能够修改文件任意位置的内容，同时不改变光标位置也不导致文本 滚动。修改文件中的日期标记的示例: :map <F2> msHmtgg/Last [cC]hange:\s*/e+1<CR>"_D"=strftime("%Y %b %d")<CR>p'tzt`s 保存位置命令的拆解: ms 将光标位置存入位置标记 's' H 跳转到窗口的顶端 mt 将光标位置存入位置标记 't' 恢复位置命令的拆解: 't 跳回先前到达的窗口顶部行 zt 滚屏，将该行滚动到窗口的顶端 `s 跳回光标初始位置 更高级的方法可见 winsaveview() 和 winrestview() 。

提升外部命令执行速度 speed-up

某些情况下，外部命令执行会很慢。Unix 上通配符展开也会随之变慢。以下是提速建议: .cshrc 文件 (文件名依所用外壳而定) 过长时，可以拆成两段: 交互配置、非交互配置 (后者常被称作二级外壳)。在 Vim 中执行一个 ":!ls" 等外部命令时，不需要交互配置 部分 (如提示符设置)。可将无关 (交互配置) 部分放到以下判断句之后: if ($?prompt == 0) then exit 0 endif 另一种办法是在 'shell' 选项中包含 "-f" 参数，例如: :set shell=csh\ -f (反斜杠用于在选项值中保留空格)。 该设置会使 csh 完全跳过 .cshrc 文件加载。但这可能造成部分功能失效。

压缩帮助文档 gzip-helpfile

磁盘空间紧张时，可压缩帮助文档。帮助文档仍可正常查看，但速度稍慢，且需依赖 "gzip" 程序。 (1) 压缩全部帮助文档: "gzip doc/*.txt"。 (2) 编辑文件 "doc/tags"，用 ".txt.gz" 替换 ".txt": :%s=\(\t.*\.txt\)\t=\1.gz\t= (3) 在 vimrc 文件中加入: set helpfile={dirname}/help.txt.gz {dirname} 为帮助文档所在目录。 gzip 插件负责解压文件。 压缩后的 "doc" 目录和其他 Vim 文件不在同一位置时，要确保 $VIMRUNTIME 设为其他 Vim 文件所在目录。参见 $VIMRUNTIME 。
