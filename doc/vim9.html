1. 什么是 Vim9 脚本？ Vim9-script Vim 脚本随着时间的推移日益庞大，同时还需要保持向后兼容。这意味着，过去做出的一 些错误设计决定往往已无法更改，而与 Vi 的兼容性也限制了解决问题的方式。此外， Vim 脚本的执行速度较慢，因为每条命令在每次执行时都需要先进行解析。 Vim9 脚本的主要目标是大幅提高性能。为此，Vim 会将命令编译为可高效执行的指令。 执行速度有望提高数十倍甚至上百倍。 次要目标是尽量避免 Vim 特有的语法结构，使其更接近 JavaScript、TypeScript 和 Java 等主流编程语言。 只有放弃 100% 的向后兼容性，才能实现所需的性能提升。例如，如果函数参数必须通过 "a:" 字典访问，就会产生相当大的开销。其他差异则不那么明显，例如错误处理方式的 变化。 Vim9 脚本的语法、语义和行为适用于以下情形: - 使用 :def 命令定义的函数 - 首条命令为 vim9script 的脚本文件 - 在上述上下文中定义的自动命令 - 使用 vim9cmd 命令修饰符的命令 在 Vim9 脚本文件中使用 :function 时，函数仍采用老式语法，并使用最高的 scriptversion 。不过，这种用法容易引起混淆，因此不建议使用。 Vim9 脚本和老式 Vim 脚本可以混用。无需重写旧脚本，它们仍会像以前一样运行。但对 需要高效执行的代码，可考虑用若干 :def 函数编写。 :vim9[cmd] {cmd} :vim9 :vim9cmd 使用 Vim9 脚本语法、语义和执行方式来解析和执行 {cmd}。在手动键 入的命令、 :function 定义的函数和老式脚本里都可用。 下列简短示例展示了老式 Vim 脚本命令和 :vim9cmd (因此采用 Vim9 脚本上下文) 之间的异同。两者外观相似，但区别不止在于语法，还有 语义和执行方式。 call popup_notification('entrée'[5:] \ ->str2list()->string(), #{time: 7000}) vim9cmd popup_notification('entrée'[5 :] ->str2list()->string(), {time: 7000}) 备注: 1. 之所以输出结果不同，是因为 Vim9 脚本使用字符索引，而 老式 Vim 脚本使用字节索引 - 见 vim9-string-index 。 2. 语法也有区别。Vim9 脚本里: - "[5 :]" 里的空格是必需的 (见 vim9-white-space )。 - 续行符 "\" 则并非必需。 - "#" (以避免给字典键加上引号) 既非必要，更不合法 - 见 #{} 。 E1164 :vim9cmd 不能单独使用；必须后跟其他命令。 :leg[acy] {cmd} :leg :legacy 使用老式脚本语法、语义和执行方式来解析和执行 {cmd}。只在 Vim9 脚本或 :def 函数里有用。要得到和上例等价的结果 (上例备注说明 了输出结果为何不同): vim9script # 老式脚本上下文 - 弹窗显示 [769, 101] legacy call popup_notification('entrée'[5:] \ ->str2list()->string(), #{time: 7000}) # Vim9 脚本上下文 - 弹窗显示 [101] popup_notification('entrée'[5 :] ->str2list()->string(), {time: 7000}) 和老式 Vim 脚本一样，Vim9 脚本中的脚本局部变量可用前缀 "s:"， 但 Vim9 脚本中该前缀可选，因为变量缺省就是局部于脚本。下例展示 了此语法差异: Vim9 脚本中可用 "k" 访问脚本局部变量，而老式 Vim 脚本中须用 "s:k"。 vim9script var k: string = "Okay" echo k legacy echo s:k E1189 在已编译的 Vim9 脚本控制流上下文中，不支持 :legacy 。示例: vim9script def F_1189() if v:version == 900 # E1189: 不能将 :legacy 用于此命令： endif legacy endif enddef F_1189() E1234 :legacy 不能单独使用；必须后跟其他命令。

8. 理据 vim9-rationale :def 命令 插件开发者一直希望 Vim 脚本性能可进一步提升。调查发现，继续保持原有函数调用语 义，性能提高很难实现，因为涉及的函数调用、局部函数作用域的创建以及逐行执行都会 带来额外开销。还有大量细节需要处理，例如错误信息和异常处理。为 a: 和 l: 作用域 创建字典、维护 a:000 列表等，都带来了无法避免的巨大负担。 因此新增 :def 用于定义新式函数，采用一套不同的语义。多数功能不变，但部分特性 有所有改动。经过考虑，引入全新函数定义方式，是隔离老式风格代码和 Vim9 脚本代码 的最佳方案。 使用 "def" 定义函数源自 Python。其他语言使用的 "function" 关键字会和老式 Vim 脚本冲突。 类型检查 将 Vim 命令行编译为指令时。应尽可能在编译阶段完成全部工作，推迟到运行时处理会 拖慢执行速度，相关错误仅能在更后阶段发现。例如，如果遇到 "+" 字符时，如果编译 成通用加法指令，运行时必须检查参数类型，判断执行的是哪种加法。遇到字典类型则抛 出错误。如果编译时确定类型为数值型，就可用 "数值相加" 专用指令，速度更快。错误 能在编译阶段捕获，运行时无需错误处理，因为两个数值相加几乎不会出错。 备注: 稍为离题一下，唯一例外是结果超出整数最大值的整数溢出。例如 64-位有符号整 数相加，结果大于 2^63: vim9script echo 9223372036854775807 + 1 # -9223372036854775808 echo 2->pow(63)->float2nr() + 1 # -9223372036854775808 复合类型使用 <type> 的写法参考 Java，易于理解且应用广泛。类型名沿用 Vim 原有名 称，但有 "void" 和 "bool" 等新增。 移除冗余和怪异语法 一旦决定 :def 函数可以和老式函数有不同的语法，我们就有自由优化语法，让熟悉主 流编程语言的开发者更容易上手。也就是去掉 Vim 独有的、反直觉的语法。 同时清理冗余语法，大多是为兼容古老 Vi 命令而遗留的设计。 示例: - 调用函数不再需要 :call ，表达式求值也不再需要 :eval 。 - 续行不再需要前导反斜杠，可以自动判断表达式何处终止。 但这也带来部分改动: - 注释改用 #
