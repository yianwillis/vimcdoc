1. 简介 windows-intro window

小结: 缓冲区是文件在内存中的文本。 窗口是缓冲区的视图。 标签页是一组窗口的集合。 "窗口" 是缓冲区的视图。可用多个窗口观察同一个缓冲区，也可用多个窗口观察不同的 缓冲区。 "缓冲区" 是一块内存区域，保存等待编辑的文件。在把缓冲区写回文件前，原始文件不 会被更改。 缓冲区存在三种状态: active-buffer 激活: 缓冲区在窗口中显示。有对应文件时，文件内容已读入缓冲区。但缓冲区内容 可能已被修改，而与磁盘上的文件内容不一致。 hidden-buffer 隐藏: 缓冲区未显示。有对应文件时，文件内容已读入缓冲区。其余属性同激活缓冲 区，只是不可见。 inactive-buffer 非激活: 缓冲区未显示，也不含任何文本。曾经加载过文件时，缓冲区相关选项会被保 留。包括来自 viminfo 文件的位置标记，但缓冲区无文本内容。 以表格形式说明: 状态 在窗口显示 文件加载 ":buffers" 命令显示 激活 是 是 'a' 隐藏 否 是 'h' 非激活 否 否 ' ' buffer-reuse 每个缓冲区拥有唯一编号，在同一次 Vim 会话中，编号保持不变。 bufnr() 和 bufname() 函数可用于在缓冲区名称和编号间相互转换。有一个例外: 新建空白缓冲区 且未作修改时，加载其他文件会重用该缓冲区。缓冲区编号也保持不变。 Vim 主窗口可容纳多个分割窗口。此外还有使用标签页 tab-page ，每个标签页可容纳 多个窗口。 window-ID winid windowid 每个窗口拥有唯一标识符，称为窗口 ID。在同一次 Vim 会话中，该 ID 保持不变。 win_getid() 和 win_id2tabwin() 函数可用于在窗口/标签页号和窗口 ID 间相互转 换。窗口还有窗口编号，每当有窗口打开或关闭，编号都可能发生变化，见 winnr() 。 窗口号仅在特定标签页内有效，而窗口 ID 在所有标签页中均有效。对大多数接受窗口 ID 或窗口号的函数，窗口号仅适用于当前标签页窗口，而窗口 ID 可引用任意标签页中 的窗口。

2. 启动 Vim windows-starting

Vim 启动后缺省只有一个窗口，和 Vi 一致。 -o 和 -O 参数可为参数列表里的每个文件单独打开一个窗口。 -o 会水平分割窗 口；而 -O 会垂直分割窗口。同时使用 -o 和 -O 时，以最后一个为准。下例会打 开三个水平分割窗口: vim -o file1 file2 file3 使用 "-oN" 格式 (其中 N 为十进制数值) 时，会打开 N 个水平分割窗口。如果文件数 量多于窗口数，仅打开 N 个窗口，其余文件没有对应窗口。如果窗口数多于文件数量， 则末尾多出的窗口会编辑空白缓冲区。"-ON" 使用相同限制，但采用垂直分割。 如果打开文件过多，每个窗口都会变得很小。可设置 'winheight' 和 'winwidth' 选项 保证窗口大小可用。 新建窗口或读取文件时，不触发 Buf/Win Enter/Leave 等自动命令 autocommand ，仅 当真正进入缓冲区/窗口后才会触发。 status-line 状态行用于分割窗口。选项 'laststatus' 控制最后一个窗口是否显示状态行: 'laststatus' = 0 永不显示状态行 'laststatus' = 1 存在多个窗口时显示状态行 'laststatus' = 2 总是显示状态行 可通过设置 'statusline' 和 'statuslineopt' 选项调整状态行内容与高度。二者均可 设为窗口局部选项，实现每个窗口状态行样式和高度独立。 状态行缺省用反色显示。可修改 'highlight' 选项中的 's' 字符调整高亮。例如 "sb" 代表粗体。如果状态行不启用高亮 ("sn")，则当前窗口使用 '^' 字符标识，其他窗口使 用 '=' 标识。有鼠标支持且用 'mouse' 选项开启后，可拖动状态行调整窗口大小。 备注: 如果期待状态行使用反色显示，但实际未生效。检查 'highlight' 选项是否包含 "si"。在 3.0 版本里，"si" 用于状态行反色 (invert)。但新版应改用 "sr" (reverse)， 因为 "si" 现在代表斜体 (italic)！如果终端不支持斜体，状态行仍会以反色显示；因 此，此问题仅会在有斜体终端能力项的终端出现。 filler-lines 窗口中缓冲区末行之后的显示行称为填充行。缺省填充行以波浪号 (~) 字符开头。可用 'fillchars' 选项中的 "eob" 项修改此字符。该字符缺省使用 NonText ( hl-NonText ) 高亮。要修改填充字符高亮，可修改 EndOfBuffer 高亮组 ( hl-EndOfBuffer )。
