1. 总览 Vim9-class-overview 专业术语叫 "面向对象编程"。这个主题有大量的学习资料。本文档假定读者已掌握相关 基本概念，着重说明 Vim9 脚本提供的功能，并附带有效使用此类功能的有助提示。 Vim9 类和对象不支持老式 Vim 脚本和老式函数。 基础单元是对象: - 对象保存状态。包含一或多个可保存值的变量。 - 对象提供函数，用于访问和操作状态。这些函数在 "对象上" 调用，这正是数据与操作 数据的代码分离的传统方式的区别所在。 - 对象有定义良好的接口，包括带类型标注的成员变量和方法。 - 对象由类创建，同一类生成的所有对象接口一致。接口并非动态，运行时无法变更。 对象只能由类创建。类提供: - new() 方法，即构造函数，返回该类的一个对象。通过类名调用: MyClass.new()。 - 类所有对象共享的状态: 类变量 (类成员)。 - 层级结构，支持超类和子类，即继承。 接口用于指定对象具备的属性: - 同一对象可声明实现多个接口。 - 实现同一接口的不同对象，可以用相同方式调用。 类层级结构仅支持单一继承。其他需要可用接口实现。 类模型 可以自由设计类模型。重点关注开发目标，不必强行映射现实世界。这点容易产生困惑， 教材常用现实事物讲解类之间的关系，会让人误以为模型必须复刻现实。不必如此！模型 应当匹配实际业务目的。 要记住组合 (一个对象包含其他对象) 通常优于继承 (一个对象扩展另一个对象)。不要 耗费时间寻找最优类模型，也不必纠结正方形是矩形还是矩形是正方形这类问题，并无实 际意义。

4. 使用抽象类 Vim9-abstract-class 抽象类用作至少一个子类的基底。在类建模中常会遇到这种情景，多个类拥有可复用的共 同属性，但仅靠这些属性，不足以创建可实例化对象的类。为此可定义抽象类。子类必须 先扩展抽象类，补齐缺失的状态和/或方法，才能够用于创建对象。 例如，Shape (图形) 类可保存 color (颜色) 和 thickness (线条粗细)。但因为缺少图 形类型信息。不能直接创建 Shape 对象。Shape 作为基类，可供 Square 和 Triangle 类继承，后两者可以实例化。例如: abstract class Shape var color = Color.Black var thickness = 10 endclass class Square extends Shape var size: number def new(this.size) enddef endclass class Triangle extends Shape var base: number var height: number def new(this.base, this.height) enddef endclass 抽象类定义方式与普通类一致，区别在于抽象类不能拥有 new() 方法。 E1359 abstract-method E1371 E1372 可在抽象类中，通过在定义前加 "abstract" 前缀，定义抽象方法: abstract class Shape abstract def Draw() endclass 抽象类中的类方法不能声明为抽象方法。 E1404 接口内的方法不能同时是抽象方法。 E1373 扩展抽象类的非抽象类必须实现所有的抽象方法。签名 (参数、参数类型及返回类型) 必 需严格一致。如果方法的返回类型为某类，子类实现可以返回该类本身或其子类的实例。 E1431 抽象基类中的抽象方法不能被直接调用。

5. 使用接口 Vim9-using-interface 上面 Shape、Square 和 Triangle 的示例，如果提供了计算面积的方法会更实用。为此 可定义 HasSurface 接口，指定一个返回数值的 Surface() 方法。本例是在上例的扩展: abstract class Shape var color = Color.Black var thickness = 10 endclass interface HasSurface def Surface(): number endinterface class Square extends Shape implements HasSurface var size: number def new(this.size) enddef def Surface(): number return this.size * this.size enddef endclass class Triangle extends Shape implements HasSurface var base: number var height: number def new(this.base, this.height) enddef def Surface(): number return this.base * this.height / 2 enddef endclass E1348 E1349 E1367 E1382 E1383 如果类声明实现某个接口，则类中必须出现接口定义的全部成员，且类型保持一致。 接口名可用作类型名: var shapes: list<HasSurface> = [ Square.new(12), Triangle.new(8, 15), ] for shape in shapes echo $'面积是 {shape.Surface()}' endfor E1378 E1379 E1380 E1387 接口只能包含对象方法和只读对象变量。接口不能包含可读写对象变量、受保护对象变 量、受保护对象方法、类变量和类方法。 接口可通过 "extends" 扩展另一个接口。子接口会继承父接口所有的对象变量和方法。 接口不能在函数内部 定义。 E1436

9. 设计思路 Vim9 类的大部分设计参考现代主流和新兴语言，例如 Java、TypeScript、Dart。语法做 了适配 Vim 脚本风格的改造，例如使用 endclass 收尾，而非用大括号包裹整个类。 面向对象语言里有些早期语法特性，在当年是创新，后来发现并非最优，但因为大量存量 代码，已经无法修改。Vim 的类系统是全新实现，因此拥有重新取舍的自由度，能够设计 出比老式语言更简洁、统一的语法，同时保持和主流语言相近的风格，降低学习成本。 一些现代语言加入了大量花哨特性，Vim 并不需要；但其中一些优秀设计可以借鉴。最终 方案是以主流语言通用范式为基础，舍弃有缺陷的设计，保留易于理解的优良特性。 设计决策遵循的核心原则: - 保持简洁 - 行为符合直觉，尽量和其他语言保持一致 - 规避重蹈覆辙 - 尽量让代码含义自明，减少开发者查阅帮助文档的必要 - 保持一致性 - 面向中等规模插件开发，而非巨型项目 使用 new() 作为构造函数 很多语言用类名作为构造函数。缺点是类名通常很长。一旦修改类名，所有构造函数都需 要同步改名。问题不大，但终究不太理想。 TypeScript 这类语言使用专用的 "constructor()" 函数名，方案更好。但代码中需要用 "new" 或 "new()" 创建实例，这和 "constructor()" 之间缺少直观关联。 Vim9 选择为所有构造函数统一使用 new() 作为方法名，调用方和构造方法之间的对应 关系一目了然。 不支持构造函数重载 老式 Vim 脚本与 Vim9 脚本都不支持方法重载，也就是不能用同名但带不同参数类型 定义多个方法。因此仅能存在一个 new() 构造函数。 虽然 Vim9 带有类型标注，技术上可以支持重载，但会显著增加复杂度。阅读一段 new() 调用时，需要推导每个实参的类型，才能判断实际调用哪一个构造函数；如果参数是其他 函数返回值，还要追溯该函数的返回类型，阅读成本很高。 实际替代方案是，多个构造函数使用不同名称，但名称必须以 new 开头。这样可以支持 多组不同参数的构造逻辑，一眼就能看清调用的是哪一个构造函数，同时可以完成严格类 型校验。 不支持方法重载 理由和构造函数一致: 参数类型经常不易直接判定，很难分辨实际调用哪个重载版本。直 接使用不同的方法名更清晰，由类型校验保证正确性。Vim9 也因此舍弃了基于重载的多 态，但实际用处不大。 单继承与接口 部分语言支持多继承。虽然某些场景有用，但会大幅复杂化类的规则。Vim 选择单继承， 通过接口声明类具备的能力，方案更简单。主流 Java 就是这套模型，足以满足 Vim 需 求，契合 "保持简洁" 原则。 类通过显式声明实现接口，直观表达类的设计目标，同时支持完整类型检查。一旦接口发 生变更，所有实现该接口的类都会被校验。不采用只要方法签名匹配就自动视作实现接口 的隐含机制，这种机制过于脆弱，容易产生隐蔽问题。 统一使用 "this.variable" 访问对象成员 很多语言访问对象变量的写法随上下文变化。有时必须写 "this." 消除歧义，声明时又 不带 "this."，风格不一致，容易混淆。 一个常见的痛点是，构造函数参数与对象变量同名，此时在函数体内必须写 "this." 访 问对象变量，其他场景又可以省略。代码里混杂带与不带 "this." 的写法，一致性差。 Vim9 类规定，要访问对象方法和对象变量，一律要写 "this." 前缀。规则简单统一。 在类内部阅读代码时，可以直接区分对象变量和其他变量。 使用类变量 通过 "static variable" 声明类变量是常见做法，此处并无新意。在 Vim9 脚本内 部，可直接通过名字访问类变量，和在方法中使用脚本局部变量很像。对象变量必须带 "this." 前缀，因此一眼就能区分变量类型。 TypeScript 在类内部访问类变量也要求写类名前缀。这存在两个问题: 类名可能很长， 占用代码空间，而且一旦修改类名，所有相关位置都要同步修改。 声明对象变量与类变量 核心取舍是变量声明是否沿用普通变量声明关键字 "var"。 TypeScript 不用: class Point { x: number; y = 0; } 仿照此方格，Vim 的对象变量本可以写成: class Point this.x: number this.y = 0 endclass 部分用户反馈，这种写法看起来更像赋值，而非声明。增加 "var" 并去掉 "this." 后， 观感得到改善: class Point var x: number var y = 0 endclass 类变量声明需要搭配 "static" 关键字，当时有几种候选方案。 方案 1: 省略 "var": class Point var x: number static count = 0 endclass 方案 2: "var" 写在 "static" 前: class Point var x: number var static count = 0 endclass 方案 3: "var" 写在 "static" 后: class Point var x: number static var count = 0 endclass 这与 `static def Func()` 的风格对齐。 是否省略 "var" 没有压倒性的优选方案。支持省略的两个理由是: 1. TypeScript 等主流语言不使用该关键字 2. 代码更简洁 但更多语言会重用变量与函数的通用声明语法来定义类变量和类方法。Vim9 的方法也重 用了普通函数声明语法。为保持一致性，最终决定，类变量声明强制要求写 "var"。 使用 "ClassName.new()" 构造对象 很多语言使用 "new" 运算符实例化对象，这种设计其实有点别扭，因为构造函数是由带 参数的方法实现，但被当作特殊关键字。TypeScript 也有 "new" 关键字，但构造函数名 为 "constructor()"，两者之间关联不够直观。 Vim9 将构造函数命名为 new()，也直接调用 new() 实例化对象，简单直白。其他语言 写 "new ClassName()"，但并不存在名为 ClassName() 的方法，而是类名为 ClassName 的类内部带另一个名字的构造函数，非常混淆。 Vim9 类的访问权限 vim9-access-modes Vim9 类支持的变量访问级别及其含义如下: public-variable 任意位置可读写 read-only-variable 任意位置可读，仅本类及其子类内部可写 protected-variable 仅本类及其子类内部可读写 方法的访问权限与之类似，但没有只读模式。 对象变量默认读权限 部分用户会觉得对象变量权限规则不对称，而这是有意设计。读取与修改是完全不同的操 作。读取没有副作用，可反复执行而不改变对象状态；修改会产生副作用，甚至会连锁影 响其他对象。 新增对象变量时，开发者一般只关注类型是否正确，并且通常在 new() 构造函数中完成 赋值。因此缺省只开放读取权限，大多数场景可以正常工作。如果尝试直接写入，会触发 报错，促使开发者思考是否应当开放写入权限，减少代码缺陷。 用下划线标记受保护对象变量 受保护对象变量，仅能在本类和子类内部读写，类外部无法访问。变量名前加下划线是直 观标识手段，不少编程语言都将其作为编码规范建议。 如果后续要改为允许外部访问，需要把所有位置的下划线全部删掉。但该变量仅在本类和 子类中出现，查找和修改工作量不大。 反过来改动成本更高: 把原本对外公开的变量改成受保护，只需在类内变量名增加下划 线，但外部所有引用该变量的代码都要逐一找到并修改，甚至要改成调用 "set" 方法。 这对应工程实践里的现实问题，即收回访问权限，需要修改全部外部调用点。 原本也可以设计 "protected" 关键字，就像 "public" 用于开放访问那样。但这里选择 不新增关键字，以此减少关键字总量。 不提供私有对象变量 部分语言提供多种访问控制修饰符。最常见的是 "protected"，不过不同语言对它的定义 并不统一。除此之外还有 "shared"、"private"、"package"，甚至 "friend"。 这类复杂规则会提升使用负担。多人协作维护大型复杂项目时，为防止重构类结构时出 错，这套机制才有价值。 Vim 脚本多用于插件开发，一般是单人或小团队维护。复杂权限规则只会增加使用成本， 这套额外安全机制并无必要。因此保持精简，不提供更细粒度的访问控制。
